一、PHP 基础语法

1.1 环境与运行

  • PHP 是服务器端脚本语言，跑在服务器（Apache/Nginx）上动态生成网页。
  • 浏览器只看到 PHP 输出的结果，看不到源码。
  • 本地环境：phpstudy（D:\phpstudy_pro），CLI 运行方式：
  • 网页运行：用 PHP 内置服务器 php -S 127.0.0.1:端口 -t 目录。

运行流程：浏览器发请求 → 服务器执行 PHP → PHP 算出结果 → 返回给浏览器。

1.2 文件结构与注释

  • PHP 代码必须包在 <?php ... ?> 里。
  • 没有 main()，脚本从上到下逐行执行。
  • 注释 // #（单行）、/* */（多行）不执行。

1.3 变量与类型

  • 变量**必须带 $**，不用声明类型（弱类型）。
  • 同一个变量可中途改类型：$x = 10; $x = "字符串";（CTF 漏洞常源于此）。
  • 未赋值变量 = NULL，输出不报错。
  • 类型自动转换："42" + 8 = 50（字符串自动当数字）。
  • 常量：define("X", 值) 或 const X = 值;。
  • 变量变量 $$：用变量的值当变量名。

1.4 运算符与比较（CTF 重点）

算术：+ - * / %（同 C）+ **（幂，C 没有）

字符串拼接：用 .（C 用 strcat）

复合赋值：+= -= *= /= .=（.= 拼接追加）

逻辑：&& || !　位运算：& | ^ ~ << >>

== vs ===（CTF 头号大坑）

运算符 比较方式 例子
== 松散：只比值，自动转类型 1 == "1" 真，"abc" == 0 真
=== 严格：值和类型都相等 1 === "1" 假

0e 魔法哈希：任何 0e 开头的字符串都被当 0，互相之间相等。

CTF 经典：md5($a) == md5($b) 且 $a != $b，找两个 md5 以 0e 开头的字符串即可通过。

数组绕过：strcmp($arr, "abc") 遇到数组返回 NULL，NULL == 0 为 true → 绕过校验。

3.2 魔术方法

以 __ 开头，PHP 在特定时刻自动调用：

方法 触发时机 CTF 价值
__construct new 时 构造

3.3 POP 链

POP = Property-Oriented Programming（面向属性编程），ROP 的属性版。

核心：攻击者不能直接调方法，只能控制属性；利用自动触发的魔术方法，把属性引导到危险函数。

3.4 __wakeup 绕过

CVE-2016-7124：序列化串里属性数 > 实际属性数时，PHP 跳过 __wakeup()。

用途：__wakeup 里若有拦截 / 校验，夸大属性数跳过它，危险操作就能执行。

1. OSI 七层模型与 TCP/IP 协议簇【已讲】

难度：入门 | 优先级：P0必学
网络是 Web 应用的 “运输管道”，你发的每个 HTTP 请求都要经过层层封装。学网络模型不是为了考试，而是为了看懂数据包在哪一层被动手脚、攻击发生在哪一层
。

完整讲解要点：

  • OSI 七层：应用 / 表示 / 会话 / 传输 / 网络 / 数据链路 / 物理

  • TCP/IP 四层（实际使用）：应用（含OSI 5/6/7）、传输、网络、链路
    用wireshark抓到的实例



    TCP三次握手的意义
    安全意义：
    端口扫描（Nmap）本质就是发 SYN 看对方回不回 SYN+ACK
    SYN 泛洪攻击：攻击者只发 ① 不回 ③，让服务器堆满半开连接耗尽资源（这是 DDoS 的一种）

  • 1. 二、两个模型的记忆方法

OSI 七层（理论模型）：物理 → 数据链路 → 网络 → 传输 → 会话 → 表示 → 应用。口诀：**”物数网传会表应”（从下往上）。
TCP/IP 四层（实际标准）：网络接口 → 网际 → 传输 → 应用。OSI 是教科书，TCP/IP 是现实**—— 你只需要真正记熟 TCP/IP 四层，OSI 能对上号就行

  • Web 漏洞发生在应用层；扫描、握手、端口属传输层/网络层

  • TCP 三次握手：SYN → SYN+ACK → ACK（建立可靠连接、协商序号）

  • 半开扫描（Nmap -sS）原理：只发 SYN，收到 SYN+ACK 即判定开放，不完成握手

  • TCP 四次挥手：FIN → ACK → FIN → ACK（服务端需先发完剩余数据）

  • TCP 可靠 / UDP 无连接（DNS、视频走 UDP）

  • 必背端口：80 HTTP、443 HTTPS、21 FTP、22 SSH、23 Telnet、25 SMTP、53 DNS、3306 MySQL、3389 RDP、6379 Redis、8080 常见后台

  • OSI七层模型与TCP/IP协议簇（已听讲解，待动手：nmap -sV 扫本机验证）

2. HTTP / HTTPS 协议详解【已讲】

难度：入门 | 优先级：P0必学

完整讲解要点：

  • 请求-响应模型：一次请求一次响应；HTTP 无状态、明文

  • 请求组成：请求行（方法 路径 版本）+ 请求头 + 请求体(POST)

  • 响应组成：状态行（版本 状态码 短语）+ 响应头 + 响应体

  • 方法：GET / POST / PUT / DELETE / OPTIONS(探测方法) / HEAD / TRACE(XST高危禁用)

  • 状态码五类：1xx 信息、2xx 成功(200/201)、3xx 重定向(301/302/304)、4xx 客户端错误(400/401/403/404/405/429)、5xx 服务端错误(500/502/503)

  • 关键请求头：Host、User-Agent、Referer、Cookie、Content-Type、X-Forwarded-For(可伪造)

  • 关键响应头：Set-Cookie、Location、Content-Type

  • HTTPS = HTTP + TLS：ClientHello → ServerHello+证书 → 验证证书 → 交换密钥材料 → 协商会话密钥 → 对称加密通信

  • 中间人攻击 = 伪造证书骗过验证；Burp 抓 HTTPS 需安装其 CA 证书

  • HTTP/HTTPS协议详解（已听讲解，待动手：Burp 抓包逐行拆解一个请求）

100.简易payload构造 重点是原理理解

分类

一、统一 Payload 构造流程（所有漏洞通用）

  1. 定位可控输入点
    找页面可输入位置：URL GET 参数 / 表单 POST / Cookie / 请求头。确认这个输入会被后端代码处理。
  2. 初步探测，确定漏洞类别
    使用上表探测语句发包，观察页面返回（报错、弹窗、内容变化）确定漏洞。
  3. 语法闭合（注入类漏洞最关键）
    后端代码已有固定语法，Payload 第一步要闭合原有引号 / 括号，写入恶意语句，最后注释掉后端剩下的代码，防止语法报错。
    • SQL：'闭合单引号，-- -注释剩余 SQL
    • 命令执行：; | & 命令分隔符，拼接新命令
  4. 编写基础 Payload
    根据漏洞类型，套用模板，实现目标（查库、执行代码、读文件等）
  5. 过滤 / WAF 处理（Payload 被拦截时）
    关键词被过滤：大小写变形、编码、字符串拼接、注释插入绕过
  6. 编码处理
    GET 参数 < > & ' " 等特殊符号建议 URL 编码；Burp 选中内容右键可直接编码
  7. 发包验证
    Burp 抓包修改参数，Forward 发送请求，查看响应包，判断 Payload 是否执行成功
  8. 迭代优化
    基础 Payload 失效，分析过滤规则，改写 Payload 再次测试
