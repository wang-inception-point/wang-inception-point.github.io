171 题（Web-SQL注入 / 联合查询绕过过滤）

关键过滤：username != 'flag' —— 数据库里有个用户叫 flag，但直接被过滤了，正常查询查不到它。

注入点：源码里 id = '".$_GET['id']."' limit 1;"，用户输入被单引号包裹后拼进 SQL。

AND 和 OR 的优先级（本题关键）

SQL 和 C 一样，运算符有优先级：AND（且）比 OR（或）优先。对照 C：&& 比 || 优先级高。

所以这条：

不是从左往右读，而是 and 先结合：

  • 左边：username!='flag' 且 id=1 → 查出 admin（正常用户）
  • 右边：username='flag' → 把 flag 行也拉进来

因为 OR 只要右边成立，这行就会被选中 → 绕过了 !=flag 的排除。

一句话：and 要求两边都成立（收紧），or 只要一边成立（放宽）。出题人用 !=flag and 想挡住你，你用一个 or username='flag' 把”后门”打开，flag 就溜出来了。

最终 payload

  • 1' 用单引号闭合前面的 id='1
  • or username=flag 打开第二扇门
  • %23 是 # 的 URL 编码，注释掉后面残留的 ' limit 1;，否则多出来的引号不配对 → SQL 语法错误

复盘清单

知识点 应用
注入点判断 找 '...' 包裹 + 直接拼接的位置
闭合引号 用 ' 逃逸出字符串
注释 用 # / -- 吞掉残留（输入框用 %23）
优先级绕过 AND 优先 OR，用 or 打开第二扇门

union 使用准则

  1. 前后两条 select 列数量必须一样。原语句 select username,password 是 2 列，后面也要 2 列。
  2. 对应位置的数据类型尽量兼容（第一列对第一列，类型差别太大可能报错）。
  3. 默认 UNION 自动去重；UNION ALL 不去重，速度更快。CTF 注入用 union select 就行。
  4. union 是拼接两个查询的结果集，前后是两条独立查询，where 条件互不干扰。
  5. 想只显示后面注入的结果：让前面查询查不到数据，常用 id=-1。
  6. limit 只作用于离它最近的那一条 select，不是全局。
  7. order by 也是作用于整个合并后的结果集。

一句话速记：列数相等、位置对齐、类型兼容；前句置空，只看我们的数据。

第一关：intval 进制绕过

源码关键逻辑：

限制：

  1. $num == 411413 → 不能直接等于 411413（宽松比较）
  2. preg_match("/[a-z\\.]/i") → 不能有字母和点
  3. strpos($num,"0") → 必须含 0，且 0 不能在第 0 位
  4. intval($num, 0) === 411413 → intval 自动进制解析后必须等于 411413

intval 的进制规则

intval($num, 0) 按数字前缀自动判断进制：

  • 0x 开头 → 十六进制
  • 0 开头 → 八进制
  • 其他 → 十进制

411413 要让 intval 自动进制解析后等于它，且字符串里必须包含 0 又不能有字母，所以应该用八进制。411413 的八进制是 01443425。

但 0 又不能在首位（strpos 要求 0 不在第 0 位），所以应加 +。在 PHP 函数中解析数字时会先识别符号判断正负号，后面沿用判断得到的数：+01443425 → 因为有了 + 占了零号位，故 0 在一号位，成功绕过 intval("+123") 结果是 123。

3. 构造过程（关键坑逐个排）

坑1：B 的 __wakeup 会把 action 置 null

必须绕过 __wakeup。经典手法（CVE-2016-7124）：序列化对象时声明的属性数 > 类实际属性数，则 __wakeup 不触发。 B 类只有 1 个属性，所以写 O:1:"B":2:{...}（声明 2 个，实际只列 action）。

坑3（核心）：字符逃逸的 N 值 & 尾巴覆盖

错误公式（之前一直没打通）：inject = ";s:4:"sign";，再把 B 串拼后面，N = len(inject)+len(b) → 溢出量比 B 串还长，B 被吃掉，sign 解析为空/乱。

正确做法：

  1. inject 要自含完整内容，且 N = len(inject)，这样溢出量刚好等于 inject。
  2. inject 结尾必须加 ;} 关闭 A 对象，让原生尾巴 ";s:4:"sign";s:1:"x"; 变成尾随垃圾被忽略——否则原生 sign 字段会覆盖我们注入的 sign。
  3. sign 字段要直接跟对象，不能包成字符串：
    • ❌ s:203:"O:1:\"B\"... → sign 是字符串，echo 不触发 __toString
    • ✅ O:1:"B":... 直接作为 sign 值 → sign 是对象，A::__destruct echo 时触发链
